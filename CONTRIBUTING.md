# Contributing

Thanks for your interest. Contributions of any size are welcome.

## Ground rules

- Open an issue before large changes so we can agree on scope.
- One logical change per pull request.
- Keep commits and PR titles descriptive; squash-merge is the default.
- New behavior needs tests. Bug fixes need a regression test.
- Run linters and tests locally before pushing.

## Development

```sh
# clone
git clone https://github.com/lowlydba/{repo}.git
cd {repo}

# install / build / test
```

## Pull requests

1. Fork and create a topic branch from `main`.
2. Make your change with tests and docs.
3. Ensure CI is green.
4. Open the PR and link any related issue.

## Reporting security issues

See [SECURITY](SECURITY.md). Do **not** file public issues for vulnerabilities.
